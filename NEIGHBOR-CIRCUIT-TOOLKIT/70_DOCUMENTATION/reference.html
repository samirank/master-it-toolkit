Windows Recovery Commands

Record the symptom, recent changes and error codes. Check disk detection and health before repairing Windows. If the source is unstable, follow the failing-disk workflow first. Confirm owner-held encryption recovery access.

  1. Boot Windows RE from recovery options or official installation media; choose Repair your computer.
  2. Try Startup Repair for startup failures. For recent regressions, consider uninstalling the latest update or System Restore.
  3. For a booted system, inspect Reliability Monitor and Event Viewer, then use DISM and SFC when corruption is suspected.
  4. Back up before repair installation or reset; “Keep my files” is not an independent backup.
perfmon /rel
eventvwr.msc
reagentc /info

Command Prompt commands and PowerShell cmdlets use different syntax. Open an elevated terminal only when required; do not paste an entire cheat sheet as a script.

DISM Commands

Run elevated on the intended installation. /Online means the currently running Windows installation, not internet connectivity. CheckHealth reads an existing corruption flag; ScanHealth performs a scan.

DISM /Online /Cleanup-Image /CheckHealth
DISM /Online /Cleanup-Image /ScanHealth
DISM /Online /Cleanup-Image /RestoreHealth

For a local WIM repair source, inspect available indexes first. Replace MEDIA and INDEX; the source must match the target architecture, edition, language and suitable servicing level. /LimitAccess prevents Windows Update fallback.

DISM /Get-WimInfo /WimFile:MEDIA:\sources\install.wim
DISM /Online /Cleanup-Image /RestoreHealth /Source:wim:MEDIA:\sources\install.wim:INDEX /LimitAccess

An ESD source uses esd: in place of wim:. In WinRE, /Online targets WinRE itself: identify the actual offline Windows directory and use /Image: with the verified drive path. Review Windows\Logs\DISM\dism.log. Do not run ResetBase casually; it removes update-uninstall options.

SFC

After component-store repair, check protected system files. Run elevated. Review the final message and CBS.log; reboot and recheck if instructed.

sfc /verifyonly
sfc /scannow

For offline repair, first locate the offline Windows and boot directories. SFC /offwindir and /offbootdir must use those verified paths; drive letters often change in WinRE. Do not assume C: is Windows.

CHKDSK

CAUTION / HIGH RISKImage a failing disk before filesystem repair or repeated surface scans. CHKDSK /f modifies filesystem metadata; /r adds a full sector scan and heavy read load.
chkdsk C:

Without repair switches this reports filesystem state. On healthy backed-up NTFS media, /scan is an online scan; /f repairs errors and may schedule a restart for the system volume. Confirm the correct volume before accepting. Do not use CHKDSK as a data recovery tool.

Official reference: CHKDSK command ↗ (requires internet)

DiskPart

CAUTION / HIGH RISKCLEAN, CLEAN ALL, FORMAT and DELETE can destroy partition information or data. This guide provides inventory commands only. Do not select a disk from capacity alone: verify serial/model externally.
diskpart
list disk
list volume
exit

Disk Management provides a graphical view. An “initialize disk” prompt on a previously used drive may signal damaged metadata: cancel it if data recovery is needed. RAW does not mean empty. DiskPart commands must be entered inside DiskPart, not directly into PowerShell.

Bootrec / BCD / EFI

CAUTION / HIGH RISKBCD changes and EFI formatting can prevent booting or trigger BitLocker recovery. Do not format EFI or use blanket bootrec recipes without identifying the actual layout.
bcdedit /enum all
reagentc /info

Record UEFI/GPT versus BIOS/MBR mode. In WinRE, use DiskPart list volume to identify Windows and the existing EFI System Partition. Unlock encrypted Windows using the owner-provided recovery key when required.

BCDBoot can rebuild boot files from a verified Windows directory to a verified system partition. Its /s and /f arguments depend on the actual system. Bootrec /fixmbr is for MBR boot-code repair; it is not a universal UEFI fix. Bootrec /scanos can help inspect installations; /rebuildbcd changes the store. Prefer Startup Repair first.

netsh winsock reset

SMART / NVMe Health

smartctl --scan
# Substitute the device returned by scan:
smartctl -a /dev/DEVICE

Interpret model-specific attributes, error logs, media errors, pending/reallocated sectors, wear indicators and temperature together. A PASSED summary is not proof of health. USB bridges and RAID controllers can hide attributes or need explicit device options. Avoid long self-tests on failing media before imaging. CrystalDiskInfo is the convenient Windows view; smartctl is useful in Linux rescue environments.

GNU ddrescue

CAUTION / HIGH RISKHIGH RISK: a wrong source/output can overwrite data. Stop and use a recovery lab for mechanical damage or irreplaceable data. No command here defeats encryption.
  1. Record the source serial; avoid mounting the source read-write.
  2. Mount a healthy destination with room for the entire source image and mapfile; exFAT/ext4/NTFS support large files, FAT32 does not.
  3. Replace every ALL_CAPS placeholder. Use an image file as output, never an unverified disk device.
  4. Keep the mapfile with the image. Recover from a copy of the image to another healthy location.
lsblk -o NAME,SIZE,MODEL,SERIAL,FSTYPE,MOUNTPOINTS
# First pass: skip scraping; IMAGE and MAP belong on healthy storage.
sudo ddrescue -n /dev/SOURCE /mnt/HEALTHY/source.img /mnt/HEALTHY/source.map
# Optional bounded retry after reviewing source behavior:
sudo ddrescue -r1 /dev/SOURCE /mnt/HEALTHY/source.img /mnt/HEALTHY/source.map

These are templates, not ready-to-run commands. Preserve the original mapfile and consistent device identity across sessions. More retries can worsen a failing drive. Normal dd lacks ddrescue’s resumable recovery strategy.

Filesystem Mounting

CAUTION / HIGH RISKRead-only mounting may still replay a filesystem journal unless a filesystem-specific no-replay option is used. Image evidence or failing media first; a hardware write blocker is stronger protection.
findmnt
lsblk -f
# Only after verifying the partition and filesystem:
sudo mkdir -p /mnt/source
# ext4: read-only, no journal loading
sudo mount -t ext4 -o ro,noload /dev/PARTITION /mnt/source
# XFS: read-only, no recovery replay
sudo mount -t xfs -o ro,norecovery /dev/PARTITION /mnt/source

Choose only the command for the identified filesystem. NTFS needs a suitable read-only driver; do not clear Windows hibernation or Fast Startup metadata to force write access. BitLocker needs the legitimate key and supported unlocking tools. Unmount before disconnecting media.

Safe Mode

From a running PC, use Shift + Restart or Settings → System → Recovery → Advanced startup. In Windows RE: Troubleshoot → Advanced options → Startup Settings → Restart, then choose Safe Mode. Windows Hello PIN may be unavailable; confirm the owner can sign in with the appropriate password.

Prefer a temporary Startup Settings selection. Persistent msconfig Safe Boot can cause a loop when credentials, encryption or boot configuration are problematic. Networking in Safe Mode may lack Wi-Fi support.

Official reference: Windows support ↗ (requires internet)

Windows Recovery Environment

reagentc /info

Run elevated to inspect the registered recovery environment. A missing/disabled WinRE requires diagnosis of the recovery image and partition; do not repartition automatically. If Windows cannot reach recovery, boot matching official installation media and choose Repair your computer.

Startup Repair, System Restore, uninstall updates and command prompt are separate choices. Reset/reinstall may remove applications and data; back up first.

BitLocker Recovery — AUTHORIZED SYSTEMS ONLY

  1. Verify ownership or service authorization. Record the recovery-key ID shown on screen, not the secret key in dashboard notes.
  2. Have the owner check their Microsoft account recovery keys, work/school account or contact the organization’s IT administrator.
  3. Also check owner-held printed or saved copies. Match the key ID to the device’s prompt.
  4. The owner enters the matching recovery key on the affected system. Do not retain it in service notes.
  5. If unavailable, investigate approved escrow/backups. Microsoft cannot recreate a lost key. Resetting an encrypted device loses inaccessible data.
manage-bde -status
CAUTION / HIGH RISKBitLocker cannot be bypassed by this toolkit. Authorized account recovery does not defeat encryption. Before firmware or TPM changes, verify recovery access and follow vendor guidance on suspension and resumption.

Driver Troubleshooting

  1. Identify exact PC model, Windows build and architecture. In Device Manager, read device status and Hardware IDs.
  2. Stage offline network drivers first. OEM packages may contain custom audio, power or switchable-graphics support absent from generic packages.
  3. Choose only the matching signed package. SDIO package availability is not proof of the best match.
  4. Review a recent driver rollback before using aggressive cleanup. For GPU cleanup, stage replacement drivers and use DDU in Safe Mode if justified.
  5. Restart, verify error codes and reproduce the original workload.
pnputil /enum-drivers
Get-NetAdapter | Format-Table Name,Status,LinkSpeed

Export an existing machine’s third-party drivers to a dedicated destination when useful; the export may not include vendor applications or every prerequisite. Never apply a whole driver library blindly.

Official reference: PnPUtil ↗ (requires internet)

Malware Workflow

  1. Isolate active compromise and confirm whether incident-response evidence must be preserved.
  2. Back up required data carefully; do not copy unknown executables or persistence into a clean system.
  3. Use trusted media and fresh definitions. Microsoft Safety Scanner expires 10 days after download.
  4. Inspect Autoruns, services, scheduled tasks and browser extensions. Validate signatures; a signed file alone is not proof of safety.
  5. Patch Windows and software. Confirm Defender/firewall are enabled.
  6. Rotate compromised credentials from a clean device. Reinstall from trusted media when cleanup cannot establish confidence.

Some scanners need current signatures or online services. Keep regional availability and organizational policy in mind when choosing rescue media.

Official reference: Microsoft Safety Scanner ↗ (requires internet)

Account, OOBE & OneDrive — AUTHORIZED SYSTEMS ONLY

Agree account type, OneDrive, business integration and AI preferences before setup. Supported local-account and OOBE options differ by Windows edition/build. Use official unattended settings and validate them in a VM against the exact image; no universal setup bypass is promised.

The supplied autounattend.xml only configures language/keyboard. It includes no passwords, disk operations, auto-logon, product keys or bypass commands. Keep it in the template directory until deliberately selected for installation media.

OneDrive & Windows Backup

Confirm Files On-Demand, sync status and known-folder backup. Ensure required cloud files are downloaded and independently backed up before unlinking or uninstalling. Review actual Desktop/Documents/Pictures locations afterward. Office setups may need OneDrive, Teams and Microsoft 365 retained.

Hello/PIN & account recovery

Let the owner use the supported “I forgot my PIN” or account recovery flow. Check network, date/time, work/school policy and alternative sign-in methods. Do not delete authentication databases or attempt unauthorized password changes.

Data Recovery

Stop writing to the source. Healthy accidental deletion and failing-media recovery are different cases. Recover to another drive; installing recovery software on the source can overwrite deleted data.

  1. Image unstable media first, or escalate if physical failure is suspected.
  2. Use DMDE or TestDisk for filesystem-aware inspection; review any partition writes separately.
  3. PhotoRec carves by file signature when metadata cannot be recovered; folder structure and names may be lost.
  4. Verify recovered files by opening representative and critical documents, not just counting filenames.

SSD TRIM, overwritten data and unavailable encryption keys can prevent recovery. Keep original media until the owner accepts the outcome.

Imaging & Cloning

For healthy drives, Rescuezilla offers a graphical workflow and Clonezilla offers repeatable imaging/deployment. Disk2vhd targets virtual disk capture, not a direct replacement for bare-metal rescue imaging. Commercial Reflect/Veeam workflows have different licensing, installation and recovery-media requirements.

CAUTION / HIGH RISKDestination data will be overwritten during restore/clone. Match serial numbers, ensure adequate capacity and verify the source backup. Failing sources belong in the ddrescue workflow.

After cloning, test boot with the original disconnected. Confirm encryption, Windows activation, applications and files. Keep the source untouched until handover is approved.

Hardware, Stress Testing & Firmware

CAUTION / HIGH RISKMonitor temperatures before and during stress testing. Ensure stable power and correct model/firmware before flashing.

Use HWiNFO/CPU-Z/GPU-Z for identification and sensor baselines. MemTest86+ exercises RAM outside the OS. Prime95 emphasizes CPU/memory, FurMark emphasizes GPU load, OCCT targets selected subsystems, and Cinebench provides a repeatable rendering workload.

Return overclocks to defaults before baseline diagnosis. Stop on overheating, errors, power instability or unusual sounds. A passing stress test does not prove all workloads are stable.

Firmware is manual only: verify exact model/revision, update prerequisites, release notes, AC power/charged battery and recovery-key access. Record versions and follow the vendor’s BitLocker suspend/resume instructions. Do not flash an unrelated “similar” model.

Windows Update, Services & User Profiles

Windows Update

  1. Record error code, available space, clock, connectivity and any managed update policy.
  2. Restart and use the supported troubleshooter / Get Help. Review Windows Update history and component-store health.
  3. If cache reset is justified, preserve logs first, stop only the relevant update services, rename (do not blindly delete) SoftwareDistribution and catroot2 caches following Microsoft’s procedure, restart services and recheck.
  4. Do not reset service ACLs, delete registry keys or unregister large DLL lists from an unreviewed generic script.

User profile

Confirm free space, disk health and User Profile Service events. Back up user files, check with an authorized temporary test profile, then migrate data deliberately. Preserve EFS certificates and cloud-only data. Do not delete ProfileList entries or the original profile without a verified recovery plan.

Windows Installer

Inspect msiserver state, installation logs, pending restart and the vendor’s repair/uninstall path. A demand-start service can legitimately be stopped. Re-registering services is an escalation step, not a routine cleanup action.
